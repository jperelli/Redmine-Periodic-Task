# Changelog

## Unreleased

### Features

- Cron-less scheduling: a plugin setting runs the checker in the background from ordinary Redmine requests, throttled by an interval and a DB lock **requires migration** ([#154](https://github.com/jperelli/Redmine-Periodic-Task/pull/154)) (@jperelli)
- `GET|POST /periodictask/check?key=<sys API key>` endpoint to trigger the checker from an external scheduler ([#154](https://github.com/jperelli/Redmine-Periodic-Task/pull/154)) (@jperelli)
- Scheduler log on the plugin configuration page (last 50 runs, idle runs grouped) with a *Run checker now* button **requires migration** ([#154](https://github.com/jperelli/Redmine-Periodic-Task/pull/154)) (@jperelli)
- REST API (JSON/XML): list, show, create, update, delete and `run_now` under `/projects/:project_id/periodictask`, plus `/admin/periodictasks.json` ([#174](https://github.com/jperelli/Redmine-Periodic-Task/pull/174)) (@jperelli)
- End condition: `Ends` on a date and/or after N scheduled runs, shown in the lists, the detail page and the API **requires migration** ([#176](https://github.com/jperelli/Redmine-Periodic-Task/pull/176)) (@jperelli)
- `Previous issue open` setting: create anyway, skip the occurrence, close the previous issue first or wait and restart from its closing date ([doc](doc/if-previous-open.md)) **requires migration** ([#173](https://github.com/jperelli/Redmine-Periodic-Task/pull/173)) (@jperelli)
- Preview of the next occurrences: rule as a sentence, next 5 run days and a mini calendar on the task page, live in the form ([#170](https://github.com/jperelli/Redmine-Periodic-Task/pull/170)) (@jperelli)
- Per-task `Non-working days` option moving a run that falls on a non-working day to the next or previous working day **requires migration** ([#171](https://github.com/jperelli/Redmine-Periodic-Task/pull/171)) (@jperelli)
- `Assignee rotation`: generated issues are assigned in turn to an ordered list of members (duty roster) **requires migration** ([#169](https://github.com/jperelli/Redmine-Periodic-Task/pull/169)) (@jperelli)
- Attachments on periodic tasks, copied onto every generated issue and by the `Copy` action ([#172](https://github.com/jperelli/Redmine-Periodic-Task/pull/172)) (@jperelli)
- `**PREVIOUS_ISSUE**` variable and a *Previous generated issue* relation target linking each issue to the previous occurrence ([#168](https://github.com/jperelli/Redmine-Periodic-Task/pull/168)) (@jperelli)
- `Periodic task` issue filter and column, a recurrence marker next to generated issues and an *All issues generated by this task* link ([#175](https://github.com/jperelli/Redmine-Periodic-Task/pull/175)) (@jperelli)
- `Create periodic task from this issue` link on the issue page, prefilling the new task form ([#167](https://github.com/jperelli/Redmine-Periodic-Task/pull/167)) (@jperelli)
- `Copy` action prefilling the new task form from an existing task, inspired by [@vegaminer](https://github.com/vegaminer)'s fork ([#163](https://github.com/jperelli/Redmine-Periodic-Task/pull/163)) (@jperelli)
- `Administration` > `Periodic Tasks` page listing the tasks of every project, inspired by [@rkteam](https://github.com/rkteam)'s fork ([#162](https://github.com/jperelli/Redmine-Periodic-Task/pull/162)) (@jperelli)
- `Active` flag to disable a task without deleting it (`Run now` still works) **requires migration**, inspired by [@Luckyvb](https://github.com/Luckyvb)'s and [@rkteam](https://github.com/rkteam)'s forks ([#161](https://github.com/jperelli/Redmine-Periodic-Task/pull/161)) (@jperelli)
- Configurable `Target version` for the generated issues **requires migration** ([#161](https://github.com/jperelli/Redmine-Periodic-Task/pull/161)) (@jperelli)
- Shifted date macros `**NEXT_MONTH**`, `**NEXT_WEEK**`, `**NEXT_WEEKISO**`, `**NEXT_MONTHNAME**` and the year companions `**NEXT_MONTH_YEAR**`, `**NEXT_WEEK_YEAR**`, `**NEXT_WEEKISO_YEAR**`, `**PREVIOUS_MONTH_YEAR**`, `**WEEKISO_YEAR**`, from [@tq89](https://github.com/tq89)'s fork ([#153](https://github.com/jperelli/Redmine-Periodic-Task/pull/153))
- Day offset on the date variables (`**DAY-1**`, `**MONTHNAME+10**`), inspired by [@ash-r1](https://github.com/ash-r1)'s fork ([#159](https://github.com/jperelli/Redmine-Periodic-Task/pull/159)) (@jperelli)
- Vietnamese (`vi`) translation, adapted from [@tq89](https://github.com/tq89)'s fork ([#160](https://github.com/jperelli/Redmine-Periodic-Task/pull/160)) (@jperelli)

### Fixes

- Task pages only find tasks of the project in the URL: a member of one project could open, edit, run or delete the tasks of any other project by id ([#165](https://github.com/jperelli/Redmine-Periodic-Task/pull/165)) (@jperelli)
- A run locks the task row and re-checks that it is still due, so simultaneous triggers (cron, web scheduler, endpoint, `Run now`) no longer create two issues for one occurrence ([#169](https://github.com/jperelli/Redmine-Periodic-Task/pull/169)) ([#176](https://github.com/jperelli/Redmine-Periodic-Task/pull/176)) (@jperelli)
- `business day` intervals and due dates follow Redmine's *Non-working days* setting instead of the `business_time` gem's Monday–Friday; the gem is gone and due dates in business days were counted in calendar days ([#171](https://github.com/jperelli/Redmine-Periodic-Task/pull/171)) (@jperelli)
- `business day` intervals keep the scheduled time of day and no longer skip a day ([#79](https://github.com/jperelli/Redmine-Periodic-Task/issues/79), idea from [@chris85618](https://github.com/chris85618)'s fork) ([#155](https://github.com/jperelli/Redmine-Periodic-Task/pull/155))
- A `day`, `month` or `year` task checked at exactly its scheduled time moves to the following occurrence like the other units ([#170](https://github.com/jperelli/Redmine-Periodic-Task/pull/170)) (@jperelli)
- `**PREVIOUS_MONTH**`/`**YEAR**` and `**WEEKISO**`/`**YEAR**` rendered an inconsistent year around New Year; see the year companions above ([#153](https://github.com/jperelli/Redmine-Periodic-Task/pull/153))
- The assignee is optional: unassigned tasks follow Redmine's default assignee rules ([#166](https://github.com/jperelli/Redmine-Periodic-Task/pull/166)) (@jperelli)
- The category is optional in the form too, as it already was in the model and the API (@jperelli)
- The REST API renders `if_previous_open`, `last_skipped_issue`/`last_skipped_at` and `effective_next_run_date` (@jperelli)
- The checker restores the request locale after running, so *Run checker now* flashes in the admin's language ([#165](https://github.com/jperelli/Redmine-Periodic-Task/pull/165)) (@jperelli)
- Disabled and last-error markers were invisible on Redmine 6+/7; they now use the sprite icons, also in the admin list ([#165](https://github.com/jperelli/Redmine-Periodic-Task/pull/165)) (@jperelli)
- Sort `business day` intervals by duration in the project list ([#165](https://github.com/jperelli/Redmine-Periodic-Task/pull/165)) (@jperelli)
- Apply the `Project` patch (`has_many :periodictasks, dependent: :destroy`) at plugin load; the nested `to_prepare` never ran outside code reloading ([#154](https://github.com/jperelli/Redmine-Periodic-Task/pull/154)) (@jperelli)
